These gates run off-machine because the dialog is handed a **committer
callback** rather than a configurator. No component, no library, no
document — just widgets under the offscreen platform.

## 2. The contract, which is the whole of this phase

- a dialog is **given** a payload and **returns** a payload;
- it never writes to a component and never writes to the document;
- committing is the configurator's, through `applyArgument()`, which
  offers the payload to the live component first and records it only if
  the component accepts — B2's rule, untouched;
- **nothing is committed until the user asks.**

That last one is the difference between these windows and the inline
editors in the dock, which commit on every `valueChanged`. Fine for a
spin box; wrong for a window with a Cancel button, because a Cancel that
left half the typing behind would be a lie. It is also the property a
careless refactor is most likely to lose — wiring a `textChanged`
straight to the committer would leave every gate green but one. That
mutation is **B1**.

## 3. Decisions worth your eye

**The committer is a callback, not a pointer to the configurator.** The
dialog knows nothing about who is listening, which is D8's rule (one
document, several views, no view holding another) and is also the only
reason the gates run without a build.

**OK closes only if the component took it.** A window that shut on a
refusal would throw the user's work away and take the explanation with
it. Mutation B2.

**The refusal shown is the component's own message, verbatim.** The
component knows why it said no and we do not; replacing it with
something of the Composer's invention is mutation B5.

**A parse error is the dialog's refusal, not the component's.** There is
a `validate()` hook on the base, run before the committer. Handing
malformed text on so the component can reject it would report a typing
mistake as a modelling one and send the user looking at their model
instead of at the brace they left open. Every typed dialog in U2c will
want this hook — a table with a bad cell, a duration that is negative.

**A dialog with no committer says so.** A dead Apply button that reports
success is the hardest kind of bug to notice, because everything looks
like it worked. Mutation B4.

**The strip is built empty and kept, never shown and hidden.** A strip
that appears resizes the window under the cursor at the exact moment the
user is reading why their value was refused.

**One window per argument, raised rather than reopened.** Two windows on
one argument would let a user apply two different payloads in an order
they did not choose, and the second would silently win.

**Windows close when the component changes.** A window editing an
argument of the component being navigated away from still holds a
committer pointing at this configurator; applying from it would write a
payload to whichever component happened to be shown by then.

## 4. What the falsifier corrected

**B10 survived at first**, and it mattered. Emptying `hydrate()` left the
gate green, because `payload()` falls back to what the window opened with
whenever the text will not parse — and empty text does not parse. So a
window that hydrated **nothing at all** would show the user a blank box
and still answer `payload()` correctly. The gate now checks the *editor's
text*, not only the accessor.

**B9 did not compile**, which is not a falsified gate. Its non-greedy
pattern matched `validate()`'s `is_discarded` check four lines earlier
than intended and swallowed two whole functions. Re-anchored on a comment
unique to `payload()`'s branch.

Watch **`test_configurator`**. Each argument row is now a `QWidget`
holding the editor *and* an *Edit…* button, rather than the editor alone.
Any case that reaches a row's field widget by `m_form->itemAt(...)` and
casts it straight to a `QSpinBox` will need one hop through the container
— the editors keep their existing object names (`argument_<id>`), so
`findChild` lookups are unaffected. If a case breaks, that is the layout
change and not a behaviour change; tell me which and I will adjust it.

## 6. Look at it

1. Select a component with arguments. **Every row now has *Edit…***, and
   the inline editor still works exactly as before — that has not moved.
2. Press *Edit…*: a window opens showing that argument's payload as JSON,
   titled with the argument's caption and carrying its description.
3. **Type an edit and press Cancel.** Nothing changes — not the inline
   editor, not the document. This is the property worth checking by hand.
4. Type an edit and press **Apply**: the dock's inline editor updates and
   the window stays open. Press **OK**: it applies and closes.
5. **Break the JSON** (delete a brace) and press Apply: a message in the
   strip, the window stays open, and nothing reaches the component.
6. Type a value the component will refuse and press Apply: **the
   component's own message** appears in the strip.
7. Press *Edit…* twice on the same argument: the existing window is
   raised, not duplicated.
8. With a window open, **select a different component**: the window
   closes.
9. Open windows for three different arguments at once and move them
   around over the map — they are modeless, which is what the Mesh and
   Geometry editors in U2c will need.
