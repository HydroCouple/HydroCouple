## 1. What U1 delivers

The user's ask was "the welcome screen should be closeable just like the
openswmm.gui". That is U1a. U1b is what makes closing it a loss rather than a
relief — and it changed shape once the field evidence arrived (§3).

| Piece | Files | Status |
|---|---|---|
| Close button on the **welcome tab only**, at the side the style asks for; the page is removed, not deleted | `src/ui/composermainwindow.cpp/.h` | needs this build |
| **Help ▸ Welcome** and a ribbon **View ▸ Start ▸ Welcome** face bring it back where it was, as the same page | `src/ui/composermainwindow.cpp` | needs this build |
| Recent list management: a **Clear list** button that goes dead when the list is empty, and a context menu offering **Open** / **Remove from List** | `src/ui/welcomepage.cpp/.h` | **proven** (Qt 6.4 harness, 4/4, 6 mutations bite) |

the ribbon face reuses the existing `welcome.svg`.

## 2. Four Qt facts this was built on, measured rather than assumed

Probed against Qt 6.4 under Fusion before any code was written
(`probe.cpp`/`probe2.cpp`/`probe3.cpp`, scratch — not shipped):

1. **`SH_TabBar_CloseButtonPosition` answers RightSide under Fusion**, and a
   button can be set on one tab while the others keep none. `setTabsClosable(true)`
   would have put one on the composition, the map and the 3D view.
2. **`removeTab` leaves the page parented to the `QStackedWidget`** — alive,
   hidden, not a stray top-level window. The defensive `setParent(this)` I was
   about to write would have been dead code, so it is not there.
3. **`QTabBar` does not delete a tab button when its tab is removed.** A fresh
   button per restore leaks one orphan onto the bar per cycle — measured: four
   restores left four (the baseline two are QTabBar's own scroll buttons). So
   there is exactly one button, created once and re-installed. Mutation **T6**
   restores the leak.
4. **Qt already picks the right next tab.** Closing the start page *while on it*
   moves to the composition; closing it *from the map* stays on the map. My
   first draft called `setCurrentWidget(m_canvas)` unconditionally — that is not
   redundant but **wrong**, and it would have yanked you off a map you were
   reading. The line is gone; gate `ClosingTheStartPageFromAnotherTabLeavesYouOnIt`
   and mutation **T3** hold it down.

## 3. One scope change, with the evidence

**The Examples section is dropped from U1 and folded into F3.** The plan said
to list "the SDK's shipped example compositions (found through the SDK's install
prefix — no copies)". Two things are false in that sentence:

- The SDK **installs no examples** — `HydroCoupleSDK/install/Darwin/share/hydrocouplesdk/`
  contains only `schema/`. The examples exist only in the SDK's source tree.
- `examples/serial_coupling/composition.json` **names no libraries and no
  component-info references** — its components are resolved by that example's own
  `main.cpp` through a caller-supplied `ComponentResolver`, which is the SDK's
  design (it deliberately has no registry). Opened in Composer it would draw two
  *unavailable* boxes.

An Examples list whose entries open to red boxes is worse than no Examples list.
Shipping a worked example needs a demo component in the bundle, which is
packaging work — and the plan already has a home for it: **F3, "Docs + examples
… seeded with two worked examples"**. Recorded there rather than invented here.

**What replaced it** is driven by what the U7 verification actually found: your
real plist holds **nine recent entries pointing at deleted temp directories**
from test runs made before the settings redirect existed. `RecentCompositions`
has had `clear()` and `forget()` since `fb24baa` with **no UI at all**. So U1b is
list management — which openswmm.gui also has ("Clear Recent Files"), which fixes
a real mess on your machine, and which is reachable by a test.

Also deliberate: **closing the page does not touch the start-up preference.**
They are different questions — "not now" and "not ever" — and the preference has
its own box on the page and its own row in the dialog.

## 5. Test

```bash
ctest --preset Darwin --output-on-failure 2>&1 | tee verification/u1/ctest.log
```

`test_welcome` goes from 6 cases to 12. The six new ones:

| Case | What it proves |
|---|---|
| `TheRecentListCanBeEmptiedAndEntriesDropped` | Clear empties the store and then goes dead; forgetting one entry updates the list, because the page is a view of the store |
| `TheRecentMenuOpensAndForgetsButOffersNothingOnThePlaceholder` | Open asks the window (so opening still records it as recent), Remove acts on the store, and the "nothing opened yet" row offers no menu at all |
| `OnlyTheWelcomeTabOffersToClose` | the welcome tab has a close button and **no other tab does** |
| `ClosingTakesTheTabAndKeepsThePage` | the tab goes, the page survives and is not a stray window, the start-up preference is untouched, and a second click is harmless |
| `ClosingTheStartPageFromAnotherTabLeavesYouOnIt` | closing from the map leaves you on the map (fact 4 above) |
| `HelpWelcomeBringsItBackAsTheSamePage` | it returns at index 0 with its icon, its recent list intact and **the same close button object** (a new one would mean the old leaked); triggering it again selects rather than duplicates |

ASan, as every slice since C3a:

```bash
cmake --build build/asan --target test_welcome test_shell_smoke
for t in test_welcome test_shell_smoke; do
  QT_QPA_PLATFORM=offscreen ASAN_OPTIONS=detect_leaks=0 build/asan/tests/gui/$t
done 2>&1 | tee verification/u1/asan.log
```

Falsifier — all 13 must print `CAUGHT`. Every pattern was dry-run against the
current source, so a `NOT APPLIED` means the source moved after this was written:

```bash
BUILD=build/darwin verification/u1/falsify_welcome_tab.sh 2>&1 | tee verification/u1/falsify_welcome_tab.log
```

W1–W6 (the page) already bite in the off-machine harness; T1–T7 (the tab) are
the ones this run proves. **T6 and T3 are the two worth watching** — they are
the leak and the wrong-tab bug that the probes caught.

## 6. Look at it

```bash
build/darwin/composer_screenshot artifacts/composer-welcome.png
build/darwin/composer_screenshot artifacts/composer-welcome-closed.png --welcome-closed
```

Then in `build/darwin/HydroCoupleComposer.app`:

1. The **Welcome tab has a small ✕**; the Composition, Map and 3D tabs do not.
2. Click it. The tab goes, you land on **Composition**, and the log says
   *"Start page closed — Help ▸ Welcome brings it back."*
3. **Help ▸ Welcome** (and the ribbon **View ▸ Start ▸ Welcome** face) brings it
   back **first, with its icon**, showing the same recent list as before.
4. Switch to the **Map** tab, then click the Welcome tab's ✕ from there: the tab
   goes and **you stay on the map**.
5. Close and restore it half a dozen times, then close it once more — no
   stray buttons pile up on the tab bar, and the ✕ still works on the last one.
6. **The nine stale entries:** right-click one → *Remove from List*; it goes and
   the others stay. Then **Clear list** → the list reads *"Nothing opened yet."*
   and the button goes grey. Right-click that placeholder row: **no menu appears**.
7. Relaunch. The list is still empty, and the start page still opens first —
   closing it in step 2 did not change the start-up preference.
8. Untick *Show this page on start up*, relaunch: opens on Composition, and the
   page is still reachable from Help ▸ Welcome.
