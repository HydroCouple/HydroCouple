# U2-S — Typed arguments answer their typed interfaces: hand-off

**Written:** 2026-09-20 · **Repo:** HydroCoupleSDK ·
**Phase:** U2-S of the Composer's `plans/COMPOSER_UX_COHERENCE_PLAN_2026-09-19.md`
· **Pairs with:** Composer `6b05fc1` (U2a) · **State:** uncommitted here.

---

## 1. Why this is in the SDK at all

`IArgument` derives from `IComponentDataItem`, so an argument that holds
a time series or a mesh *can* say so. Until now none did, and every
consumer had to infer it: a time series looked like a rank-1 column of
numbers, and a mesh looked like a shape of `{ nodes, 3 }` — which reads
as a coordinate table and loses every face.

The Composer's U2a shipped the classification that reads these
interfaces. Without this slice those branches are correct and never
taken by an SDK argument: the classifier is ready and has nothing to
classify.

## 2. What changed

| Class | Now also | Methods |
|---|---|---|
| `TimeSeriesArgumentDouble` | `ITimeSeriesComponentDataItem` | `time`, `timeCount`, `times`, `timeSpan`, `timeDimension` |
| `PolyhedralSurfaceArgument` | `IPolyhedralSurfaceComponentDataItem` | `meshDataObjectType`, `meshDataType`, `polyhedralSurface`, `patchDimension`, `edgeDimension`, `vertexDimension` |

Additive in both cases: each class keeps every base it had, and
`static_assert`s in the new test pin that it is still an `IArgument`.

**Nothing is stored twice.** The Julian days already live in the
`TimeSeries` and are handed out as a span over that vector; the mesh
already lives in the argument and the surface is built from it on demand.

## 3. Two caches, and why neither can go stale

**The time series validates per slot.** `time(i)` compares the cached
`TimeData`'s Julian day against the series' own value at that index and
rebuilds if they differ. That is *exact*, not a heuristic: an `IDateTime`
here **is** its Julian day, so a slot whose day still matches is still
the right answer no matter what was reloaded around it. Same for the
span, which is its start and its duration.

This matters because there are four places that load a series today —
CSV text, CSV file, JSON, and copying from another data item — and a
fifth would have silently skipped any invalidation hook. The cache
cannot go stale because it never trusts itself.
`ReloadingASeriesDoesNotHandOutTheOldDates` is the gate, and both series
in it have three times, so a size check alone would not save it.

**The surface uses one door instead.** A `MeshDefinition` has no cheap
identity to validate against, so the four assignments to `m_mesh` were
funnelled through a new private `adoptMesh()`, which assigns and drops
the cached adapter. A cache invalidated at four call sites is a cache
that will be stale at the fifth; there is now one.

## 4. Judgement calls worth your review

- **`meshDataObjectType()` is `Vertex`, not `Cell`.** The argument's own
  values are the node coordinates — `shape()` is `{ nodes, 3 }` — so what
  this data item is *about* is vertices. A consumer reading `Cell` would
  look for one value per face and find one per node.
- **`meshDataType()` is `Vector`.** Three components per vertex: a
  position, not a scalar field.
- **`vertexDimension()` returns the argument's existing
  `m_nodeDimension`**, not a new one. `shape()` is already indexed by it,
  and a second dimension object meaning the same thing is a second thing
  that can disagree about how many vertices there are. Only `patch` and
  `edge` are new.
- **`polyhedralSurface()` returns nullptr when no mesh is loaded.** An
  empty surface would be reported as a fact about the argument ("zero
  faces") rather than as "nothing loaded yet", and acted on.
- **`timeSpan()` returns a zero span rather than nullptr for an empty
  series**, so a caller asking what an unloaded series covers gets
  "nothing" rather than a pointer to test. The asymmetry with the surface
  above is deliberate: a span of zero is a meaningful answer, a surface
  with no faces is not.
- **The adapter is given the `MeshDefinition` as well as the surface.**
  `meshadapters.h` is explicit that a surface built without connectivity
  reports no faces and no edges, and that this "is not a lesser answer —
  it is a wrong one". Mutation S8 restores that bug.

## 5. What was verified here, and what was not

Verified off-machine, against the real headers:

- both translation units **syntax-check clean**;
- the new test's `static_assert`s **pass**, which is the part that
  matters most: `-fsyntax-only` will happily compile a class that still
  has a pure virtual, because the error only appears where something
  instantiates one — and adding an interface is exactly the change that
  leaves one behind. The asserts instantiate the trait instead;
- all 14 falsifier patterns **apply** (dry-run), so none can report a
  silent `NOT APPLIED`.

Not verified here — needs your build:

- the runtime gates in `tests/hydrocouplesdk/test_typedarguments.cpp`
  (6 cases), which is where the cache behaviour is actually exercised;
- the falsifier itself.

## 6. Build, test, falsify

```bash
cmake --build --preset Darwin 2>&1 | tee verification/u2s/build.log
ctest --preset Darwin --output-on-failure 2>&1 | tee verification/u2s/ctest.log
BUILD=build/Darwin verification/u2s/falsify_typedarguments.sh 2>&1 \
  | tee verification/u2s/falsify_typedarguments.log
```

`test_typedarguments.cpp` is new and registered in `tests/CMakeLists.txt`.

Note the falsifier has two mutation kinds. Most must turn a gate red; **S1
and S2 must fail to compile** — removing a base class leaves a pure
virtual behind, and the `static_assert`s are what notice. The script
reports a build failure as the catch for those two and as a *survival*
for the others, so read its output rather than its exit code alone.

Watch **`test_temporal`** and **`test_spatialarguments`**: both construct
these classes, and both should be unaffected — if either changes, the
addition was not as additive as it looks.

## 7. Then, on the Composer side

With this in, U2a's typed branches start firing for real. Worth
confirming once: open a composition whose component has a time-series
argument and check the descriptor now reports `TimeSeries` rather than
`Table`. The dock will still *draw* a table — that is `inlineKind`, by
design, until U2b and U2c give each kind a dialog.
