# Provider Pipeline Program ("ARGGEN") — 2026-09-03

Arguments generated by components: mesh generators, timeseries providers
(and eventually optimizers) as HydroCouple components whose outputs
initialize other components — orchestrating delineation → parameterization
→ execution → analysis → visualization entirely from HydroCoupleComposer.

This is the program's hub document. Cross-linked from:
- `HydroCouple/plans/composer/COMPOSER_MODERNIZATION_PLAN_2026-08-24.md` (B5b, S4.x, O1-O5)
- `HydroCouple/plans/sdk/COMPOSITION_IO_AND_RESULTS_PLAN.md` (§9)
- `FVQUAL/plans/FVQUAL_FEASIBILITY_AND_DEVELOPMENT_PLAN_2026-08-23.md` (F8.1)

## Context

The interface spec was *designed* for this and the connection is simply
unfinished: `IArgument::initialize(const IComponentDataItem&, string&)`
exists precisely "so that outputs from one model can be used as
initialization arguments for another" (hydrocouple.h:1703-1710), with
`validComponentDataItemTypes()` as the type-negotiation channel;
`ComponentStatus::Finished` guarantees readable outputs after completion;
`TimeSteppedWorkflow` already skips Finished components;
`ExecutionMode::Open` + `ResultsModelComponent` already embody "run
standalone, consume the recorded results as a component"; and
`ModelInitializer` already calls `argument->initialize(item, msg)` — but
only for `@ref` sidecar files, never a live `IOutput`.

Missing: document syntax for "argument X comes from component A's output
Y", topological staging in `ModelInitializer`, spatial argument classes,
provider components, FVQual's plugin entry point, and the Composer UX.

User decisions (2026-09-03): providers live in a **new HydroCoupleComponents
repo**; FVQual carries **both** a met-forcing argument and the live exchange
input; Composer credentials at rest via **machine-bound AES** (clean-room);
optimizer is a **design note only** this program; the timeseries provider
is **comprehensive** — multiple file formats and web services (USGS NWIS
first), dispatched automatically.

## Governing decisions

- **D1 — Zero interface-spec (HydroCouple repo) changes.** Everything needed
  exists. Only a non-normative doc paragraph describing the provider pattern.
- **D2 — Binding syntax is SDK-owned `@from`, Composition Spec v1.1.**
  Per-argument payload: `"mesh": {"@from": {"component": "meshgen",
  "output": "mesh", "selector": null}}`. Joins the existing `@uri`/`@ref`
  sigil family; schema-visible so `CompositionSpec::parse` builds the
  binding DAG and refuses cycles naming the edge; headless `--run` and
  Python resolve identically. Supersedes the Composer plan B5b's
  "`$from` Composer convention". `schema_version` → "1.1", purely
  additive; 1.0 documents stay valid.
- **D3 — Resolution is a staged pre-pass in SDK `ModelInitializer`, not a
  workflow extension.** Workflows are constructed after components
  initialize — too late by definition. Topo-sort components by `@from`
  edges (document order within a stage; binding-free documents behave
  byte-identically); before a consumer's `initialize()`, run each bound
  provider to `Finished` via a private `runToFinished()` (initialize →
  validate → prepare → bounded update loop), then locate the provider
  `IOutput` and call `argument->initialize(*output, msg)` — the exact path
  `SidecarSourceItem` already exercises. `serialize()` re-emits the
  *reference*, never the baked value. Providers already Finished
  (ExecutionMode::Open → ResultsModelComponent) resolve with zero extra
  machinery — how pathway (b) unifies with pathway (a). New
  `setProgressCallback` (stage/component granularity) and exported
  `bindingStages(const CompositionSpec&)` for hosts.
- **D4 — Q9/Q10/Q11 (Composer plan B5b).** Q9: provenance-on-load,
  value-after-provider-runs — opening a composition never executes
  anything; the configurator shows a binding chip; resolution happens only
  in the run pipeline. Corollary contract: consumers keep valid defaults
  when a bound argument is unresolved, and providers do no heavy work in
  `initialize()`. Q10: whole output item only; `selector` reserved in
  schema, diagnosed unimplemented if present (house pattern:
  ExecutionMode::Resume). Q11: dangling bindings survive as repairable —
  `validateDocument` error at run, downgradable to an edit-time warning by
  the host.
- **D5 — Providers ship from a new `HydroCoupleComponents` repo**
  (`~/Documents/Projects/cbuahin_github/HydroCoupleComponents`): CMake
  `find_package(HydroCoupleSDK)`, each component a plugin library with
  `HYDROCOUPLE_DECLARE_COMPONENT`, MIT license. The *fixture* provider
  component stays in SDK tests so P1 gates don't depend on the new repo.
- **D6 — Optimizer: seam design note only.** Needs workflow-as-plugin
  (`AbstractWorkflowComponentInfo` doesn't exist) + `ICloneableModelComponent`
  orchestration — its own program. The `@from` substrate is the seam.
- **D7 — New SDK argument classes** implementing
  `initialize(IComponentDataItem&)` for real and serializing bulk via
  `@uri`/`@ref` (the spec mandates bulk payloads are never inlined):
  `PolyhedralSurfaceArgument`, `RasterArgument`, and an
  `ITimeSeriesComponentDataItem` acceptance path on `TimeSeriesArgumentDouble`.
- **D8 — Pathway (b) is connect-and-document.** Open/ResultsModelComponent/
  manifests/@uri all exist; work = bindings resolving against opened
  components (falls out of D3), an FVQual manifest-writing standalone run,
  and Composer per-component execution-mode UI.

## Phases

### P1 — SDK binding substrate (HydroCoupleSDK) — critical path

- **S1.1 Composition Spec v1.1.** Parse `@from` → typed
  `ArgumentBindingSpec`; structural cycle detection naming the edge;
  `share/schema/composition-1.1.json`. Files: `io/compositionspec.{h,cpp}`.
  Gates: parse/round-trip; cycle refused with edge named; selector
  diagnosed; a 1.0 document still parses.
- **S1.2 ModelInitializer staged apply.** Topo stages; `runToFinished`;
  live `argument->initialize(*output)`; `serialize()` re-emits the
  reference; `setProgressCallback`; exported `bindingStages()`. Files:
  `io/modelinitializer.{h,cpp}` (the `SidecarSourceItem` call site is the
  pattern). Gates: two-fixture binding (consumer receives produced value;
  document round-trips the *reference*, not the value); provider failure →
  named error; binding against an Open/ResultsModelComponent output; a
  binding-free document behaves byte-identically.
- **S1.3 Argument classes.** `PolyhedralSurfaceArgument` (File via UGRID
  read; live accept of IPolyhedralSurface/ITIN items), `RasterArgument`
  (accept IRasterComponentDataItem; `@uri` GeoTIFF path or WCS GetCoverage
  URL), TimeSeriesArgument extension. Gates: initialize-from-data-item;
  `@uri`/`@ref` serialize; never-inline-bulk falsifier.

### P2 — HydroCoupleComponents repo (new) — depends on P1

- **S2.0 Repo scaffold.** CMake + `find_package(HydroCoupleSDK)`, MIT,
  ctest harness, smoke plugin proving the ABI stamp round-trip through the
  Composer loader contract (componentabi.h is Qt-free/upstreamable).
- **S2.1 MeshGeneratorComponent.** Wraps `Tools::Triangulator`/`QuadMesher`;
  domain/PSLG argument in; IPolyhedralSurface output; optional UGRID write;
  `MeshProgress` → status events (cancelable). Gates: Finished-after-run
  with readable mesh; cancel mid-mesh; UGRID byte-parity with a direct
  Tools call (the Composer E2a delegation-gate pattern).
- **S2.2 TimeSeriesProviderComponent — comprehensive.**
  - **S2.2a Provider core + format registry.** One component,
    ITimeSeriesComponentDataItem outputs (one per series/parameter), a
    `source` argument whose scheme/extension dispatches automatically
    (`IO::uriScheme` pattern): CSV (header sniffing, datetime detection),
    CE-QUAL-W2 `.npt` (reimplemented here; FVQUAL's reader stays FVQUAL's),
    SWMM-style `.dat`, NetCDF CF timeseries (feature-gated, refusing with a
    message when absent). Gates: per-format parity fixtures; unknown format
    → Failed naming what was tried; datetime/units carried into the value
    definition.
  - **S2.2b Web services.** USGS NWIS first (IV + DV: site, parameter code,
    period arguments; JSON API), fetched through the process `UriResolver`
    seam. Every fetch cached to a local sidecar recorded beside the
    composition (offline reruns serve the cache; `sourceUri()` keeps
    provenance; refresh is explicit). Fetcher registry so NOAA/SOS join
    later without touching the core. Gates: NWIS JSON fixture via
    in-process HTTP server; cache honoured offline; refresh refetches;
    unknown site/parameter → Failed with the service's message.
- **S2.3 TerrainSamplerComponent** (stretch). Raster + mesh in → sampled
  nodal field out, wrapping `Tools::TerrainSampler`.
